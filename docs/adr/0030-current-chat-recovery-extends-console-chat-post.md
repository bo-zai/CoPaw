# Current Chat Recovery Extends Console Chat POST

`GET /api/chats/{chat_id}` is a non-blocking read of the last durable Chat History Snapshot and no longer waits for an active Answer Turn. `POST /api/console/chat` gains the opt-in `reconnect_mode: "current"`: it atomically selects the caller's current authorized Chat state, attaches its active turn when present, or emits a terminal `chat.snapshot` SSE event when no turn is active. The existing POST paths, request fields, SSE frames, and legacy reconnect 404 remain unchanged when the mode is absent or unrecognized, so third parties migrate by adding one optional field rather than adopting a separate endpoint or required Chat-ID parameter.

Current recovery is linearized with Answer Turn admission by the per-Chat coordinator lock. It accepts the existing session-shaped locator and treats an optional Chat ID as a non-blocking hint; final missing and unauthorized targets are both `404 Chat not found`. Terminal snapshots persist and return the public turn status `completed`, `stopped`, or `failed`; the settlement barrier prevents a new turn until that persistence succeeds. A write failure enters Pending Settlement Recovery: the same write is retried without rerunning the model, recovery and new submission receive retryable unavailability, and a restart reconciles any persisted admitted-but-not-active turn as `failed`. The Console falls back from a 404 to one history refresh to remain compatible with servers that do not yet recognize the new mode.
